# CHG-005 / F1-05 — Tres tareas ejecutables

> **Precondición bloqueante:** CHG-004 debe estar implementado y comprobado en el checkout con scripts `test:unit`, `test:integration` y `test:e2e` y resultados reales; solo entonces aplicar CHG-005. **No iniciar CHG-005 durante la ejecución de CHG-004.** No hacer merge/archive automáticamente.

- [ ] **1. OPS — Workflows GitHub Actions reproducibles.** Configurar workflows versionados para PRs a `main` y pushes relevantes con Node fijado desde `.nvmrc`, `npm ci`, `npm run typecheck`, `npm run lint`, `npm run check:boundaries`, `npm run build`, Vitest, PostgreSQL efímero y Playwright Chromium según scripts reales de CHG-004; dar IDs de job estables, permisos mínimos, límites de tiempo, caching y manejo de artefactos sin secretos. **Verificación:** ejecutar un PR real de control y confirmar nombres y resultados de cada job en GitHub; no declarar verde basándose solo en YAML.

- [ ] **2. SEC — Análisis de dependencias, secretos y código.** Integrar `npm audit --omit=dev` como gate obligatorio, auditoría completa con excepción acotada y vencimiento documentados para cuatro moderados de `esbuild` en `drizzle-kit`, detección mantenida de secretos y análisis estático de código (CodeQL/equivalente según capacidades). Documentar riesgos en `docs/operations/pr-quality-policy.md`, sin `continue-on-error` genérico ni degradación de Drizzle. **Verificación:** nueva vulnerabilidad o cambio de advisory causa fallo; el único riesgo aprobado queda visible; fixture sintético de secreto es detectado; análisis estático se ejecuta realmente.

- [ ] **3. QA — Protección efectiva de `main` y protocolo PR.** Revisar permisos y rulesets existentes; configurar y verificar reglas de `main` con PR obligatorio, revisión requerida y status checks observados de ejecución real, sujetos a disponibilidad GitHub. Documentar pasos de revisión, excepciones, resultados y propietarios; probar PR controlado que falla y otro que cumple sin fusionarlos. Ejecutar regresión local y `openspec validate chg-005-establish-ci-quality-gates --strict`. **Verificación:** GitHub bloquea un merge cuando falla un check obligatorio; si falta permiso o capacidad, dejar T3 abierta y reportar el bloqueo en vez de afirmar protección.
