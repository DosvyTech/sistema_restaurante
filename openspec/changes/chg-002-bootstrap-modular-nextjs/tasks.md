# CHG-002 / F1-02 — Tres tareas ejecutables

Si faltan, detener Apply y solicitar sincronización/merge; no inventarlos. No editar `main`; no archivar ni hacer merge sin instrucción. Exactamente tres tareas.

- [ ] **1. BE / Base Next.js ejecutable y frontera servidor–cliente.** Sobre la raíz existente inicializar Next.js estable con App Router, React, Node.js, npm/`package-lock.json`, `src/app`, `tsconfig.json` estricto, alias `@/*`, entorno reproducible y `server-only` en módulos exclusivos del servidor; documentar convenciones de código y los scripts necesarios sin desactivar validaciones. - [ ] **2. FE / Shell, navegación real y registros de los siete módulos.** Implementar `/`, `/modules`, layout global, navegación semántica responsive y accesible con estilos básicos; agregar registro de MOD-01, MOD-02, MOD-03, MOD-04, MOD-05, MOD-08 y MOD-09 como **planificados**, sin pantallas CRUD ficticias ni sistemas de autenticación. Mantener `src/app`, `src/modules`, `src/shared` con responsabilidades explícitas; no instalar sistema visual final de F1-08. **Verificación:** comprobar ambas rutas, enlaces, contenido en español y navegación por teclado/viewport móvil por medios efectivamente disponibles.

- [ ] **3. QA / Calidad y límites arquitectónicos automatizados.** Incorporar scripts `npm run lint`, `npm run typecheck`, `npm run check:boundaries`, `npm run build` y `npm run start`; configurar detección efectiva de ciclos e importaciones prohibidas y demostrar que falla con un caso inválido temporal; ejecutar comandos reales y `openspec validate chg-002-bootstrap-modular-nextjs --strict`, `git diff --check`; documentar versión Node/npm, resultados y limitaciones. **Verificación:** todos los gates aplicables pasan sin deshabilitaciones; no aparecen ciclos, no se filtra código server-only al cliente y la especificación OpenSpec es válida. Marcar 3/3 solo con evidencia.
