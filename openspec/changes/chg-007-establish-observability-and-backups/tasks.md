# CHG-007 / F1-07 — Tres tareas ejecutables

> **Dependencia BLOQUEANTE:** antes de Apply confirmar CHG-006/F1-06 implementado, integrado y con pruebas **locales Docker aisladas** de instalación y actualización aprobadas. El gate del VPS público sigue separado antes de producción. No confundir planificación CHG-006 con infraestructura funcional. No iniciar CHG-008, merges o archive automáticamente. Máximo 3 tareas.

- [ ] **1. OPS — Healthchecks, logs rotados y alertas ligeras.** Configurar healthchecks para Next.js, PostgreSQL y Caddy; logs estructurados con rotación y límites; alertas esenciales de caída/backup mediante notificación externa sencilla. En desarrollo puede usarse un receptor aislado sintético para probar el flujo, sin considerarlo sustituto de una notificación externa real antes de producción. Sin Prometheus/Grafana/ELK u otros servicios sin justificación. **Evidencia:** pruebas controladas de fallo y recuperación, alerta/cierre observados y ausencia de secretos en logs.

- [ ] **2. DB/OPS — pgBackRest y almacenamiento S3 de prueba aislado.** Mantener pgBackRest; ejecutar SeaweedFS `weed mini` en un proyecto Docker independiente y desechable, sin exposición pública, con imagen fijada por versión o digest, datos y credenciales sintéticos. Demostrar compatibilidad S3 real para backup cifrado, restore, archivado y recuperación WAL con las versiones fijadas. Si falla una operación requerida, evaluar y justificar una alternativa S3 compatible mantenida antes de implementarla. Producción requiere repositorio cifrado fuera del VPS, credenciales independientes y recuperación comprobada. **Evidencia:** operaciones end-to-end, `pgbackrest check/info`, WAL, pruebas de fallo, aislamiento y limpieza segura; la prueba local no acredita almacenamiento externo real.

- [ ] **3. QA — Restauración desechable y RPO/RTO observados.** Restaurar backup/PITR con datos sintéticos en una instalación PostgreSQL desechable; comprobar integridad y servicio. Registrar timestamps UTC, RPO observado (objetivo <=15m), RTO observado (objetivo <=4h), transacciones confirmadas/recuperadas, pérdidas posibles y límites de la simulación. Si se incumple o falta evidencia, no aceptar la tarea. Documentar el runbook; no extrapolar a producción ni tocar stacks existentes.
